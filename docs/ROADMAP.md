# Roadmap

V2 extends the small reusable 3D engine with validated source authoring, explicit resident state and an original articulated character. [V2 build record](V2_BUILD.md) records current acceptance; [BUILD_STATUS.md](../BUILD_STATUS.md) preserves release history. Items below describe remaining work.

## Next useful increments

1. **Independent owner/Dot pilot.** Give a new person the onboarding prompt and repository; record the questions, tool gaps, manual repairs and save/reopen result for a substantially different home.
2. **Imported skeletal rig fixture.** V2's original Node3D joint rig and scene audit work without external assets. Next, add a clearly licensed skinned GLB with verified idle/walk/interaction clips and document adaptation.
3. **World editing and recovery.** Add validated import/restore UI, explicit routine/project migrations, backups and clear owner-lock change review.
4. **Hosted persistence adapter.** Implement authenticated reads/writes, transactional revision checks, migration recovery and cross-device acceptance.
5. **More movement capabilities.** Add one explicit transition type at a time: door, stair/ramp, elevator, portal or scene boundary. Test cancellation, obstruction and return paths.
6. **Behavior extensions.** Extend V2's arrival/cleanup hook and occupancy light for effects that ordinary arrival/animation cannot express. Keep new furniture data-driven.
7. **Optional real activity adapter.** Only where an actual authorized source exists. Prove work and native-call paths separately, including missed END, replay resistance and revocation.
8. **Broader device acceptance.** Test additional desktop browsers, mobile/embedded contexts and accessibility improvements with measured performance budgets.

## Intentionally outside v0.1

Arbitrary photo-to-perfect-rig automation, multiplayer, a new calling system, endless autonomous expansion and universal native ChatGPT telemetry are not promised. Better graphics can follow verified movement, state and extension contracts. A future recurring creative task needs a bounded owner-authorized scope and actual model/tool work; it is separate from elapsed-time simulation.
