# Domes for Dots v0.2.0

V2 extends the existing Godot foundation with validated world creation and expansion, inspectable resident activity state and an original articulated character. Cedar Atelier, Tidal Observatory and the new Lantern Archive use the same runtime and local state schema.

## Changes

- A JSON proposal, plan, apply and recovery workflow checks existing owner locks, optional budgets and operation policy, stale source hashes and content validity. It preserves originals and records expansion history.
- Resident state distinguishes current and previous activity, source, target, physical location, arrival, movement and animation. Optional station preferences, tagged MOCK activities and a saved autonomy pause control extend the existing routine and event paths.
- Nova has an original articulated body with six AnimationPlayer clips. A loaded-scene audit checks character definitions and declared clips while preserving the procedural fallback.
- Lumen's Lantern Archive demonstrates creation from a complete authored proposal and a subsequent telescope expansion. This is a fictional reproducibility pilot, not an independent owner study or a live ChatGPT Dot interview.

## Verification

The V2 acceptance record reports **70 Python tests, 92 core assertions, 200 runtime assertions, 43 character assertions, three character audits and 37 exported-browser checks passing** with Godot `4.5.1.stable.official.f62fdbde1` and Chrome 154 on Windows. All 121 station pairs resolve, all 19 stations are physically visited, and 21,534 obstacle-clearance samples pass. The browser run covers all three worlds, activity routing and arrival, pause persistence, mock priority and expiry, save conflicts and recovery, exports, pointer input and the new character poses.

Read the [V2 build record](https://github.com/bslizzle8552/domes-for-dots/blob/v0.2.0/docs/V2_BUILD.md) for evidence, build provenance and precise acceptance limits. `release_manifest.json` identifies the packaged source commit; the Web build manifest identifies its tested runtime source and file hashes.

## Assets and local use

- **`domes-for-dots-v0.2.0-source.zip`** — editable Godot project, authored examples, schemas, prompts, tools, tests and documentation. Building requires Godot 4.5.1 Standard, matching Web export templates and Python development dependencies.
- **`domes-for-dots-v0.2.0-web.zip`** — prebuilt browser runtime, launch instructions, license notices and build/release manifests. Godot is not required to run it.
- **`SHA256SUMS`** — SHA-256 checksums for both ZIP assets.
- **`release_manifest.json`** — package version, source commit and validation provenance.

Extract the Web ZIP completely. In the extracted folder, run `python -m http.server 8060 --bind 127.0.0.1`, then open `http://127.0.0.1:8060` in a desktop browser with WebGL 2 support. Keep the generated filenames and `docs` folder together. Opening `index.html` through `file://` is unsupported. No public world hosting is included.

## Known limits

- Routines are SIMULATED and test events are MOCK. Native ChatGPT call/work adapters remain unavailable; the phone pose carries no audio call.
- Saves remain local to one browser profile and origin. There is no hosted synchronization, general progress migration or guaranteed atomic transaction across simultaneous writers.
- Navigation uses flat connected floors and static footprints. Civil-time schedules, multilevel movement and mobile acceptance are not provided.
- New content needs validation and a rebuild. In-app world imports, unattended model-driven expansion, automatic photo-to-3D and universal imported-rig compatibility are unavailable.
- Standing rest/work/phone poses were reviewed; prop grip and seating are not claimed. Safari, Firefox, mobile, Blender-authored rigs and an independent owner pilot remain untested.
